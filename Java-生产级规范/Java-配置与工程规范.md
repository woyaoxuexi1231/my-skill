# Java 配置与工程规范

> 范围：配置文件、环境隔离、密钥、构建/打包与工程卫生。  
> 本篇偏 **工程与配置落地**：文件怎么组织、环境怎么隔离、密钥怎么管、交付怎么算诚实。

---

## 1. 代码 vs 配置

| 放代码 | 放配置（yml/env/密钥管理） |
|--------|---------------------------|
| 稳定业务规则与分支 | DB/Redis/HTTP 地址 |
| 明确的领域常量（枚举等） | 超时、连接池大小 |
| 算法与结构 | 密钥、密码、第三方凭证 |

不要把每个魔法数字都变成配置项；**随环境变化**的才进配置。

---

## 2. 配置文件结构

推荐：

```text
application.yml                 # 公共、非敏感默认
application-{profile}.yml       # dev / test / prod 等差异
```

### 必须

- 多环境要有对应 profile 文件（或等价外部化配置）；禁止「脚本切了 `dev` 却没有 `application-dev.yml`」。
- 打包/启动时 `spring.profiles.active`（或平台环境变量）来源明确，可复现。
- 敏感值：不进 Git 明文；用环境变量、密钥服务或本地未提交文件（并在文档说明键名）。

### 禁止

- 密码、Token、私钥写死在源码或可提交的 yml 里。
- 同含义配置多个来源互相覆盖却说不清优先级。
- 仅本机偶然能跑的隐式默认（别人拉下来必挂）。

---

## 3. `@ConfigurationProperties` 与装配类

- 用类型安全的 `@ConfigurationProperties`（或项目等价方式）承接一组相关配置，避免满代码 `Environment.getProperty`。
- Java 配置类（`*Config`）只做装配与开关，**不写业务用例**（不查业务表、不推流程）。
- 一类中间件一个配置类：`RedisConfig`、`MybatisPlusConfig`；禁 `AllConfig`。

---

## 4. 数据脚本与工程卫生

- **表结构**与**种子/演示数据**分离；改表同步改种子/迁移脚本（开发期若约定删库重跑，则改脚本且删死代码，不留双轨）。
- 依赖只引入当前用到的；不预拉 MQ/Cloud/网关「以后可能用」。
- 不要为了配一个 Bean 破坏依赖方向：配置层只被业务层依赖，不反向依赖业务层。

---

## 5. 构建与交付诚实性

- 未实际执行编译/测试时，**禁止**声称「已通过」。
- 交付前至少：能编译；关键路径按项目要求自测；改过的配置在目标 profile 下能启动。
- 自测要覆盖本次改动实际影响到的路径，而不是跑通启动就算数。

---

## 6. 核对清单

- [ ] 公共配置与环境配置分离；profile 齐全可切换  
- [ ] 无密钥进库；本机能跑 ≠ 只有隐式环境  
- [ ] ConfigurationProperties / Config 类无业务逻辑  
- [ ] 未引入用不到的基础设施依赖  
- [ ] 未谎报构建/测试结果
