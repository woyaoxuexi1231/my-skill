# Java 安全规约

> 范围：权限、脱敏、注入、CSRF/XSS、防重放等**编码安全底线**。  
> `security/` 包放哪见 `Java-代码架构.md`；Spring Security 框架装配细节可按项目选型，本篇不绑死某一套 Filter 写法。  
> SQL 参数与 ORM 防注入细则亦见 `Java-模块代码规范.md`、`../MySQL-生产级规范/MySQL-数据库规范.md`。

---

## 1. 权限

- 属于用户个人的页面/接口/数据操作，必须做**权限校验**（含水平越权：不能只认「已登录」就改他人订单、读他人私信）。
- 鉴权基础设施集中在 `security/`；业务 Service 里禁止散落一套私有鉴权旁路。

---

## 2. 敏感数据

- 用户敏感数据禁止直接展示：手机号、证件号、银行卡等须**脱敏**（如 `158****9119`）。
- 日志禁止输出密码、Token、密钥、完整敏感载荷（见日志规范）。

---

## 3. 输入与注入

- 用户请求参数必须做有效性验证（长度、范围、枚举、排序字段白名单等）。忽略校验常见后果：超大 pageSize OOM、恶意 order by 慢查询、任意重定向、注入、反序列化、ReDoS。
- 访问数据库：严格参数绑定（MyBatis `#{}` / PreparedStatement）；**禁止**字符串拼接 SQL / `${}` 拼接用户输入。
- 正则校验注意灾难性回溯（ReDoS）；勿对不可信输入使用危险正则。

---

## 4. 前端输出与 CSRF

- 禁止向 HTML 页面输出未经安全过滤或未正确转义的用户数据（防 XSS）。
- 表单 / AJAX 写操作须有 CSRF 防护（Token 或框架等价机制），按项目统一启用。

---

## 5. 资源与防刷

- 使用短信、邮件、下单、支付等平台资源：必须有防重放 / 频控（次数、疲劳度、验证码等），防滥刷与资损。
- 发帖、评论、即时消息等 UGC：应有防刷与违禁词等风控策略（按业务要求落地）。

---

## 6. 核对清单

- [ ] 个人数据接口有水平权限校验  
- [ ] 敏感展示已脱敏；日志无密钥/Token  
- [ ] 入参校验齐全；SQL 无拼接注入点  
- [ ] XSS/CSRF 按形态处理  
- [ ] 短信/支付等有频控与防重放
