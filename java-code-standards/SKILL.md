# Java 生产级编码与工程规范

按项目既定的一组 Java 规范编写、审查与重构代码。规范为**整包交付物**，不是临时建议。

## 使用方式

按任务类型从 `references/` 挑对应文档精读，再落地代码或审查：

| 你要做的事                                         | 精读文档               |
| --------------------------------------------- | ------------------ |
| 定架构 / 分包 / 谁调谁                                | `Java-总体代码架构.md`   |
| 写 Controller/Service/Mapper/DTO、持久化分轨、异常、金额时间 | `Java-分层代码规范.md`   |
| Spring 依赖注入 / 事务 / 代理 / 装配                    | `Java-Spring规范.md` |
| Redis / HTTP / MQ / 外部依赖调用                    | `Java-外部调用规范.md`   |
| 日志怎么写、各类类该写多深注释                               | `Java-日志与注释规范.md`  |
| 配置文件 / 环境隔离 / 密钥 / 构建交付                       | `Java-配置与工程规范.md`  |

## 强制约定（任何任务都适用）

- **持久化分轨**：单表 → 全局单表 `mapper`（`extends BaseMapper` + Lambda）；联表/复杂 SQL → 发起模块的模块内 `mapper` + XML。禁止「多次单表查后再内存关联」。

- **业务模块优先**：`entity` / 单表 `mapper` 等公共件外置，模块内再细分 controller/service/mapper/dto。禁止全局技术层里套业务子包。

- **调度单向**：`controller → service → (模块 mapper | 全局单表 mapper) → DB`；跨模块只经对方 Service 门面。

- **方法注释一律 Javadoc**（再简也不用 `//`）；行间步骤编号用 emoji 键帽数字；日志不做数字编号，只作标记 emoji（`✅ ❌ ⚠️`）且不泄密。

- **构造器注入**；事务/异步/缓存不依赖 `this.xxx()` 自调用；Config 类只装配不写业务用例。

- 涉及任何规范细节拿不准时，回到对应 `references/` 文档的「核对清单」与「打回语」对照。

## 输出约定

- 审查/返工时使用对应文档里的**打回语**措辞，保持口径统一。

- 注释语言与用户语言一致；代码注释遵守《Java-日志与注释规范》分层详略。
