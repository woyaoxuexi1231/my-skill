# Java 学习项目 编码规范

面向**学习/实验/教程型** Java 项目的一套规范，与生产规范（`java-code-standards`）**互斥**，不混用。

## 使用方式

| 你要做的事 | 精读文档 |
| --- | --- |
| 学习项目里写注释、打日志、写原理文档注释指路 | `references/Java-学习项目-日志与注释规范.md` |

> 本套目前只收「日志与注释」一篇。学习项目的**包结构、分层、依赖注入、配置**等仍按个人习惯或沿用 `java-code-standards` 中相容的部分；只有「注释写多深、日志怎么打」这一件事，学习项目必须走本篇、不走生产篇。

## 强制约定（学习项目专用）

- **先判断项目性质**：这份代码的读者需要「被教会」还是只需要「被提醒」？前者用本篇，后者用 `java-code-standards/references/Java-日志与注释规范.md`。判断不清时，按「学习项目」处理（宁详勿略）。

- **目标：代码即教材**。读者只看代码 + 注释，不借助外部资料，就能还原这套机制是怎么跑起来的。

- **注释不分厚薄**：取消生产规范的「按类类型分级、controller 薄」策略——学习项目里 entity 字段、枚举值、注入依赖、注解含义全部要注释。

- **必写「框架在背后做了什么」**：谁在什么时候调用我、返回值被谁消费、这个注解触发框架什么动作。重写方法与回调方法尤其要写调用时机。

- **步骤编号用 emoji 键帽数字** `1️⃣ 2️⃣ 3️⃣ 4️⃣ …`（全仓库统一，不用圈号数字 `① ② ③`）。编号必须连续，删除步骤后重排；10 用 `🔟`，11 及以上无键帽时保留圈号 `⑪ ⑫`。

- **日志是运行时教具**：鼓励入口/出口日志、分支日志、脱敏后的中间值日志；日志文案与步骤注释对齐（同一件事、同一套说法，长流程带上与注释相同的步骤号）。

- **仍然不泄密**：密码、完整 Token、Authorization 头、密钥原文不落日志；要观察就打脱敏片段并注明。

## 输出约定

- 审查/返工时使用文档里的**打回语**措辞，保持口径统一。

- 注释语言与用户语言一致（中文项目写中文注释）；日志文案同理。

- 生成学习代码时，宁可多写「为什么 / 机制 / 取舍 / 坑」，也不要逐行复述代码。
