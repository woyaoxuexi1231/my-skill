# 旅游攻略详情页 – 生产级前端开发提示词 v5
## （30年资深导游 + 前端架构师双重视角 · 通用完整版）

### v3 变更：页面风格不再固定，改为「目的地驱动的动态风格系统」

* 删除写死的灰阶极简令牌与「禁止渐变 / 禁止大圆角 / 禁止阴影」等一刀切约束；
* 新增：目的地气质画像 → 11 个风格原型 → 风格令牌 `DATA.theme` → CSS 变量注入；
* 新增一致性红线：明亮底、高对比、单一原型、装饰不干扰阅读；
* 换目的地 = 换风格，北京与三亚不允许长得一样。

### v3.1 变更：禁止一切折叠交互

* 删除「内容展开收起」要求，改为铁律：所有内容默认全部可见；
* 禁止：展开更多 / 收起 / accordion / details / 点击加载更多 / 内容截断 / 分页；
* 长内容改用锚点导航 + 排版层级消化，长是专业，折叠是偷懒；
* 唯一例外：多套行程方案可用 Tab 切换，但 Tab 内不得再套折叠。

### v4 变更：从「换配色」升级为「换骨架」

用户反馈：九寨沟与景德镇生成的页面排版完全一样，只有配色不同 —— 不合格。

- 12 个原型从"配色表"重写为**版面原型**：每个定义容器宽度、网格、导航位置、Hero 形态、列表容器、标题对齐、分隔方式、内容排序轴、结构禁止项。
- 新增「第三步：结构指纹强制差异」：生成前必须填 8 个结构字段，与其它目的地交叉验证至少 5 项不同；Hero / 列表容器 / 排序轴**必须不同**。
- 新增「反模板化禁令」：禁止"顶部导航 + 居中 Hero + 全卡片网格"默认骨架；一个页面内至少 3 种容器形态（时间轴 / 里程轴 / 图录 / 日记 / 分栏 / 表格 / 编号条目 / 纯留白）。
- `DATA.theme` 新增 `layout` 子对象（container / grid / nav / hero / listStyle / titleAlign / divider / orderAxis / bleed / numbering），骨架参数由数据驱动，禁止写死在 CSS。
- 验收标准升级：**把文字全部删掉，只留骨架，仍能认出是哪个目的地**。

### v5 变更：推倒原型体系，改为「视觉创生法」

用户反馈：v4 虽然换了骨架，但整篇文档仍然是一部框架定义——12 个原型、8 项结构指纹、取值枚举、留白档位、一致性红线——读起来像在填表，生成结果仍被预设的格子收敛。

**结论：任何预置选项本身就是同质化的根源。给出选项，就会被选择；被选择，就会收敛。**

v5 因此做了减法：

- **删除全部原型**。12 个版面原型、原型对照表、结构指纹表、取值枚举、留白档位，全部作废，不再提供任何可选项清单。
- **第一步改为「找到那一个东西」**：不做气质分类（分类即框架），只找一句只有该目的地成立的、含具体物/数字/动作/感官的事实。
- **第二步改为六维提问，不设选项**：空间（注意力如何运动）、时间（节奏什么形状）、材质与光、色彩（取自具体物）、字体人格、叙事视角（这份攻略是件什么东西）。
- **新增「首发构件」强制要求**：每份攻略必须发明至少一个从未见过的结构，且能追溯到目的地的某个真实坐标（海拔/温度/楼层/潮位/窑温/里程……）。
- **解绑审美限制**：删除"禁止深色底""强调色≤15%""字体最多 2 套""禁止循环动画""只许一套原型""emoji 上限"等一刀切条款。底色由目的地决定——溶洞、夜市、极夜就该是暗的。
- **废弃「风格服务于阅读，不服务于炫技」**：该表述把"不出错"变成最高目标，是页面被压成同一条安全带的直接原因。改为**风格服务于这个地方，阅读是门槛不是目标**。
- **新增「自我审查禁令」**：禁止以"太花/太怪/看不懂""保持克制""实现复杂"为由退回安全模板；禁止先搭网页骨架再套风格。
- **验收改为唯一性三测**：匿名测试（抹掉文字还认得出吗）、移植测试（搬到别处是否立刻荒谬）、一句话测试（能否说出"为什么长这样"）。

保留的只有三条底线：正文 ≥15px 行高 ≥1.6、对比度达标、装饰不遮挡文字；以及两条硬约束：内容不得折叠、禁止外部依赖。

# 🏛️ 设计系统总纲（v5 核心变更：没有模板，只有创生）

## 唯一的铁律

**这个页面只能长得像它自己。**

本文件此前所有版本里出现过的东西——风格原型、版面原型、结构指纹表、配色清单、留白档位、原型对照表——**全部作废**。

它们不是参考，是禁区。

原因很简单：只要给出一份"可选项清单"，执行者就会去选；一旦开始选，所有目的地都会收敛到清单上最安全的那几个格子。清单越详细，同质化越彻底。

所以本版不提供任何清单。

你要做的不是"为这个目的地挑一种风格"，而是**从这个目的地身上长出一种从未存在过的版面**。

> 风格不是被选择的，是被发现的。

---

## 三条不可协商的原则

1. **没有原型。**
   不存在"这一类地方就该长这样"。黄山和张家界都是山，两个页面不允许有任何家族相似。同理，水乡与水乡、古城与古城、海岛与海岛，也都不允许。

2. **没有安全牌。**
   "留白""极简""克制""大圆角""卡片网格""顶部导航"——这些不是风格，是没想清楚时的默认输出。使用它们，必须给出来自目的地的理由。

3. **形式即内容。**
   版式不是装内容的容器，版式本身就在传达"这是个什么地方"。如果这个地方只能沿一条沟往上走，那么读者的滚动也应该只能往上走。

---

## 页面目标

这是一份能长期保存的数字旅行手册。

但它首先是一个**值得打开的作品**。

> ❌ 废弃表述："风格服务于阅读，不服务于炫技。"
>
> 这句话让"不出错"成为最高目标，于是所有页面都被压进同一条安全带里。
>
> ✅ 新表述：**风格服务于这个地方。阅读是它必须跨过的门槛，不是它的设计目标。**

好读不等于平淡。一张 1958 年的铁路时刻表很好读，一本手绘速写本也很好读。

# 🧭 第一步：找到「那一个东西」（强制，最先执行）

不要做气质分类。**分类就是框架的开始。**

你要找的是一句**只有这个目的地成立的话**——一个物理事实、一种动作、一种感官、一个数字、一种光。

示范（只为说明"具体到什么程度"，禁止照抄其结论）：

* 九寨沟：水在不同深度是不同颜色，而游客只能沿一条沟由下往上走，无法横穿。
* 景德镇：一种土在 1300℃ 之后变成另一种物质，全城的秩序围绕"窑"这个容器展开。
* 重庆：你永远说不清自己在几楼，出口可能在八层，也可能在负二层。
* 敦煌：一切都由一条走廊串起来，走廊之外是同一个方向的风沙。

要求：

* 这句话里必须有**具体物、具体数字、具体动作或具体感官**，不能是形容词；
* ❌ 禁止使用"江南水乡""塞外风光""历史悠久""民族风情"这类能套给一百个地方的词；
* **检验**：把这句话里的地名换掉，如果它依然成立，重写。

---

# 🎨 第二步：把「那一个东西」翻译成视觉语法（六维）

下面六维**只有提问，没有选项**。

你的答案必须自己推导，并且每一条都能追溯到「那一个东西」。

## 1. 空间：注意力在这片土地上是怎么运动的？

不是"单栏还是双栏"。问的是：

* 游客的注意力在这里是被**拉长**（一条沟、一条路、一条江）、被**摊开**（一片街区、一片湖、一片塬）、被**抬升**（楼层、海拔、阶地）、还是被**打散**（群岛、散点、市集）？
* 版面该怎么长，才能让读者的视线**重复这个动作**？

## 2. 时间：这里的节奏是什么形状？

流动 / 堆叠 / 循环 / 骤变 / 停滞 / 反复折返？

* 是连续不断的水 → 区块之间不要硬切，让它们首尾相接；
* 是一层压一层的沉积 → 区块用错位层叠；
* 是潮汐与昼夜 → 页面可以出现周期性明灭，或两套并置的时间刻度；
* 是骤然开阔 → 让某一屏突然从极密变极空。

## 3. 材质与光：这里的表面摸起来是什么？

粗糙 / 反光 / 透亮 / 潮湿 / 起砂 / 结霜 / 晒褪 / 覆土。

光是直射、散射、透射、反射，还是几乎没有光？

→ 决定底色质感、纹理（内联 SVG 或纯 CSS 自造）、阴影方向与软硬、边界是切齐还是化开。

## 4. 色彩：从具体物里取，不要从配色方案里取

唯一合法来源：当地真实存在的一样东西——一块砖、一汪水色、一件器物、一种食物、某个时辰的天光、一面褪色的墙。

* ❌ 禁止"主色 + 辅色 + 中性灰"这套安全配方；
* ✅ 允许单色到底，允许只有一个高饱和色，允许整页几乎没有颜色；
* ✅ **允许深色底**——如果这个地方本身就是暗的（溶洞、夜市、极夜、火山岩），暗底才是最诚实的答案。底色由目的地决定，不由"可读性建议"决定；
* 每一个颜色都要能回答：这是当地什么东西的颜色？答不上来就换。

## 5. 字体人格：这块土地会怎么写字？

问：如果在这里的墙上、票根上、招牌上、碑上、包装纸上写一行字，它会长什么样？

* 允许字重极端（100 到 900）、字距极端（0 到 1em）、字号极端（一个字占满一屏）；
* 允许竖排、混排、旋转、超大编号、手写感（系统字体栈内自选）；
* ❌ 禁止默认"黑体标题 + 宋体正文"，除非这个地方的气质真的需要；
* 只用系统字体栈，禁止外部字体文件。

## 6. 叙事视角：这份攻略是谁在说话？

这是最常被忽略、也最决定形态的一维。

它不是"一个旅游网站页面"。它可以是一件别的东西：

老导游的牛皮笔记本 / 一张铁路时刻表 / 一本手绘速写本 / 一份当地日报 / 一份测绘报告 / 一本器物图录 / 一本菜谱 / 一台监测仪器的读数屏 / 一张被折了很多次的地图 / 一叠明信片 / 一册账簿 / 一块告示牌……

**先定"它是件什么东西"，容器形态自然就出来了**——时刻表就该是表格，速写本就该是散页错位，读数屏就该是等宽数字与网格，账簿就该是密排的细行。

❌ 禁止反过来：先决定"用卡片网格"，再往里填内容。

# 🔀 第三步：发明一个从未有过的结构（强制）

**每一份攻略必须至少包含一个「首发构件」**：一个你在任何其它旅游页面上没见过的结构或组件，它直接来自「那一个东西」。

它可以是：

* 一种容器（不是卡片，不是时间轴，是别的东西）；
* 一种导航（不是顶部，不是侧边，是别的东西）；
* 一种随滚动 / 随区块变化的视觉机制；
* 一种把当地数据直接变成版面坐标的方式——海拔、温度、层数、里程、潮位、窑温、经纬度、日照角度、降水量……直接成为页面的骨架。

以下示范的是**发明的思路**，不是可抄的答案：

* 如果这地方的一切由**深度**决定 → 让页面底色随滚动深度连续变化，色卡取自真实的水色梯度；
* 如果这地方的一切由**楼层**决定 → 导航变成一栋楼的剖面，读者在楼层之间上下移动；
* 如果这地方的一切由**温度**决定 → 用一条温度刻度贯穿全页，行程按温度区间排布；
* 如果这地方的一切由**一条线**决定 → 整页只有一列，全程不出现并排。

要求：在 `DATA.theme.rationale` 里用一句话说明这个构件来自目的地的什么。

说不出来，说明它没有来源——删掉重来。

## ⛔ 仍然禁止（这不是框架，这是反套路）

* ❌ 默认骨架：顶部横向导航 + 居中大标题 Hero + 每个模块都是「标题 + 卡片网格」。
* ❌ 全篇只有一种容器：景点是卡片、美食是卡片、住宿还是卡片 = 失败。
* ❌ 所有区块标题同字号、同对齐、同装饰。
* ❌ 差异只做在颜色上。
* ❌ 复制上一个目的地用过的骨架（哪怕换了色、换了字体）。

> 以上五条不限制你"能做什么"，只禁止你"不动脑"。

```javascript
layout:{
  container:"...",   // 内容多宽？出血还是收窄？宽度是否随区块变化？

  // motionAxis:"", texture:"", edge:"", bleedRule:"", numbering:"", elevation:"", rhythm:""
}
```

## 2. 必须走 CSS 变量，但变量集不是固定清单

样式表只声明变量名与默认值，**不写死任何风格**：

```css
:root{
  --bg:#ffffff; --surface:#ffffff; --text:#111111; --text-sub:#555555; --text-muted:#888888;
  --line:#dddddd; --line-soft:#eeeeee; --accent:#333333; --accent-soft:#f0f0f0;

  --tracking:0; --density:64px; --shadow:none; --motion:normal;

}
```

必须在所有 `render*()` 之前调用 `applyTheme(DATA.theme)`，通过 `document.documentElement.style.setProperty()` 注入。

要求：

* ❌ 样式表中禁止裸颜色值（`transparent` 与阴影的 `rgba(0,0,0,x)` 除外）；
* ❌ 禁止把容器宽度、栏数、Hero 高度写死在 CSS 里；
* ✅ 允许并鼓励使用一切结构性手段实现你的想法：非对称 grid、`position:sticky` 层叠、`clip-path`、SVG 不规则容器、`mix-blend-mode`、`writing-mode` 竖排、CSS 计数器、伪元素生成图形、滚动驱动的背景/色相变化、`IntersectionObserver` 进场、`@keyframes`（只要它有来源）。
* ✅ 换目的地 = 换 `DATA.theme`，整站骨架与气质同时重生。

## 3. 装饰元素实现约束

* 纹理、母题、图形一律内联 SVG 或纯 CSS；
* 禁止外部图片、外部字体、外部 CDN；
* 装饰 SVG 必须 `aria-hidden="true"`；
* 装饰层不得压在正文之上。

# 🚫 自我审查禁令（v5 新增，直击同质化）

生成过程中，禁止出现以下想法：

* ❌ **"这样可能太花 / 太怪 / 用户看不懂" → 退回安全模板。**
  只要每个形式都有来源，它就不算花。所谓的怪，往往只是陌生。
* ❌ **"还是克制一点吧" / "留白是高级的"。**
  克制是结果，不是手段。想不清楚的人才会把"留白"当答案。
* ❌ **"先搭个旅游攻略页的架子，再想风格"。**
  顺序必须是：地方 → 形式 → 内容组织。**禁止先有网页骨架。**
* ❌ **"这个效果实现起来复杂，算了"。**
  复杂不是理由。SVG、clip-path、sticky、JS 都可以用。
* ❌ **"上一个页面这么写挺好的，沿用一下"。**
  沿用就是抄袭自己。

## 唯一性三测（生成 HTML 之前，内部完成）

1. **匿名测试**
   抹掉地名与全部文字，只看骨架、色块、纹理、节奏——能不能认出这是哪儿？

2. **移植测试**
   把这套版面搬到另一个目的地，会不会立刻变得荒谬？
   **搬过去依然成立 = 它是通用模板 = 推倒重做。**

3. **一句话测试**
   能不能用一句话说清"这页为什么长这样"？
   这句话里必须有具体物，且不得出现"好看""好读""高级""标准做法"。

三测任何一条不过，回到第一步。

# 5. 页面交互

## ⛔ 铁律：所有内容默认全部可见（强制）

游客不愿意为了看内容多点一次。

禁止任何形式的“点击才能看到正文”。

### 绝对禁止

❌ “展开更多” / “收起” / “查看更多” / “阅读全文”

❌ 手风琴折叠（accordion）

❌ `<details>` / `<summary>` 折叠块

❌ 点击加载更多、分页、无限滚动

❌ 悬停或长按才显示正文

❌ `max-height:0 + overflow:hidden` 式的折叠动画

❌ “点击展开完整介绍”“查看剩余 N 条”之类的一切按钮与链接

❌ 景点介绍只显示前 3 行、其余截断

### 正确做法

✅ 所有文字一次性铺满，页面长是应该的。

✅ 长内容靠**排版层级**消化：字号、字重、留白、分隔线、区块间距。

✅ 长内容靠**锚点导航**消化：点击直接跳到目标位置，跳转不等于隐藏。

✅ 页面长度不作为删减内容的理由。

长是专业，折叠是偷懒。

### 允许的替代手段

* 顶部 sticky 锚点导航，点击平滑滚动到对应区块；
* 每个大区块内的小节目录（同样只跳转，不折叠）；
* 右侧/底部“回到顶部”按钮；
* 区块之间用风格化的分隔线与留白做呼吸感。

### 唯一例外：行程方案 Tab

多套行程方案允许用 Tab 切换，因为它们是并列的不同方案，不是被隐藏的正文。

约束：

* Tab 只允许用于「行程方案」这一类平级内容；
* Tab 内部所有内容默认全部展开，禁止在 Tab 内再套任何折叠；
* 默认激活第一个 Tab，其余方案必须真实存在于 `DATA.itinerary` 中；
* 禁止把景点介绍、美食、住宿、贴士等内容塞进 Tab。

---

## 页面导航

长页面需要让读者能快速定位，但**定位方式由你决定，不是必须有一条导航栏**。

* 导航栏、目录页、侧边索引、页内跳章标记、回到顶部按钮、随滚动变化的进度指示……都可以；
* 也允许不做传统导航——如果这份攻略本身是一本"手册"，那么一个目录页可能比顶部导航栏更对；
* ❌ 禁止默认使用"顶部 sticky 横向导航 + 一组文字链接"这套方案，除非它由这个目的地推导出来。

要求：

* 使用原生 JavaScript 平滑滚动；
* 移动端不换行挤压、不产生横向滚动；
* 若做当前区块高亮，其视觉表现必须与整体形式同源。

# 🧓 最终原则

记住：

你生成的不是一个旅游宣传页面。

也不是一个简单景点列表。

你生成的是：

> 一个30年资深导游，把旅行经验、历史知识、路线规划、消费避坑和当地生活方式整理成的一本数字旅行手册。

游客打开之后，应该能够回答：

去哪？

为什么去？

从出发地怎么去？

什么时候去？

怎么玩？

吃什么？

住哪里？

多少钱？

哪些坑不要踩？

代码只是载体。

真正的价值是：

帮助游客完成一次更好的旅行。

所以：

内容必须丰富。

信息必须可靠。

结构必须清晰。

形式必须唯一。

代码必须优雅。

其中"形式必须唯一"的含义是：

> 这份攻略的版面，只可能诞生于这一个目的地。
>
> 它不来自任何模板、任何风格库、任何"这类地方通常长这样"的经验。
>
> 它由这个地方长出来，也只属于这个地方。

这才是一份真正专业的旅游攻略详情页。
